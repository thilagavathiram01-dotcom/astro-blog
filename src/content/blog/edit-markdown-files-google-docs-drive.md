Google rolled out native Markdown support in Docs and Drive starting October 5, 2026. You can now open .md files, edit them in the familiar Docs interface, and keep the original format. This removes the old conversion step that often broke formatting or dropped comments.

Teams that draft in Markdown and review in Docs no longer switch tools. AI agents that output structured Markdown can share files directly with humans who prefer visual editing. The feature is available to all Google Workspace customers and personal Google accounts. Rollout is gradual and may take up to 15 days.

## What Changed in Google Docs and Drive

Previously, uploading a Markdown file to Drive and opening it in Docs converted it to a Google Doc. That process could alter tables, strip comments, and create a separate file. Google acknowledged these issues in its Workspace Updates post.

Now the file stays an .md or .markdown file in Drive. Docs acts as the editor. You see a rendered view with headings, lists, tables, and clickable links. An .md indicator appears next to the title so you know the format is preserved. Drive itself shows a formatted preview instead of raw text.

Real-time collaboration, sharing, and comments work the same as on regular Docs. You do not need to write raw Markdown syntax while editing. The change helps both people and AI agents work on the same structured files without manual conversions.

Google notes that Markdown is a standard text format widely used by large language models to preserve structure such as tables, headers, and bulleted lists. Native support therefore fits current AI drafting workflows.

## Step-by-Step: Preview Markdown in Drive

Start by uploading your .md or .markdown file to Google Drive. Right-click the file and choose Open with, then Preview. The viewer shows a fully rendered document with headings, tables, and links.

At the top of the viewer you can switch between Markdown and Preview modes. Use Markdown mode if you want to inspect the raw syntax. Switch back to Preview to confirm the final layout. To start editing, open the file in Google Docs from the same menu or by double-clicking it.

No admin controls or user settings are required. The feature turns on automatically once it reaches your account.

## Step-by-Step: Edit and Collaborate in Docs

Double-click the .md file in Drive. It opens in Google Docs in Markdown Mode. Look for the .md tag next to the document title. The file remains a Markdown file stored in Drive; it does not become a Google Doc.

Edit in the rendered view. Add or change headings, lists, tables, and links using the Docs toolbar. Collaborators can open the same file, leave comments, and edit in real time. Share the file the same way you share any Drive file.

If you need to restore an earlier version, go to File then Version history. Some Docs features behave differently in Markdown Mode. Smart chips become plain text or links. Web formatting converts to plain text. Font colors, highlights, and text alignment are removed. Version history lets you recover the original if needed.

This workflow pairs well with Gemini features already available in Docs. For details on drafting and editing with Gemini, see our guide on [using Gemini in Google Docs](/blog/gemini-google-docs-help-me-create/).

## Tips for AI and Agent Workflows

AI tools often generate content as Markdown because it keeps structure without proprietary formatting. Save an agent draft as a .md file, upload it to Drive, and open it in Docs. Reviewers can comment and edit without learning Markdown syntax.

The file stays the single source of truth. You can download it later as Markdown for use in other tools or repositories. Because conversion is no longer required, comments and structure survive the round trip between agents and people.

If your team uses Gemini Notebook or other Workspace AI features, native Markdown files reduce friction when moving structured notes into collaborative documents. Keep file names clear and use consistent heading styles so agents and humans both navigate the content easily.

## Limitations to Know

Not every Docs feature carries over cleanly. Advanced formatting such as custom fonts, colors, and certain smart chips is simplified or removed. Complex tables or nested structures may render differently from a dedicated Markdown editor.

The feature is still rolling out, so some accounts may not see it yet. Check by uploading a test .md file. Official support documentation lists the exact steps and known differences.

Google Docs already supported Markdown shortcuts and paste-from-Markdown options. Those remain available. The new native file support is the bigger change for teams that treat .md as the canonical format.

## Conclusion

Native Markdown support in Google Docs and Drive closes a long-standing gap between lightweight structured files and collaborative review. You upload an .md file, preview it in Drive, and edit it in Docs while the original format stays intact. Collaboration tools, comments, and sharing work as expected.

The update is especially useful for AI-assisted writing workflows where agents produce Markdown and teams refine it together. Verify the feature on your account, test with a sample file, and integrate it into existing Drive processes.
