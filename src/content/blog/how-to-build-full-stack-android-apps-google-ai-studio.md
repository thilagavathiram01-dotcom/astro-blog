Google AI Studio now lets you turn a single prompt into a production-ready Kotlin Android app. The Build agent sets up Cloud Firestore for data persistence, Firebase Authentication with Google Sign-In, and secure Gemini API calls through Firebase AI Logic and App Check. You can preview the app in an HD browser emulator and publish it directly to your personal Google Play library.

This guide walks through the exact process using official capabilities announced on November 17, 2026. No local Android Studio install or credit card is required to start. Pair this with our guide on [adding Firebase to Android apps in Google AI Studio](/blog/add-firebase-to-android-apps-google-ai-studio/) for deeper backend details.

## What the Build Agent Does Automatically

When you describe an Android app that needs storage, login, or AI features, the agent detects those needs. After you confirm, it:

- Provisions a Cloud Firestore database with Security Rules matched to your data model.
- Enables Firebase Authentication and generates a Google Sign-In flow.
- Routes Gemini calls through Firebase AI Logic with App Check enforced so no API key lives in the APK.
- Adds the Firebase BoM and generates idiomatic Kotlin code for the data and AI layers.

Previously generated Android apps in AI Studio used only local session storage. The new flow supports cross-device sync and offline caching.

## Step-by-Step: Create Your First Full-Stack App

Open [Google AI Studio](https://aistudio.google.com/apps?features=build_android_app) and sign in with your Google account.

1. Select the Android chip at the top of the Build workspace.
2. Enter a clear prompt. Example: "Build an Android workout coach app that uses the Gemini API to generate personalized daily routines, reads cues aloud with audio, and saves workout history across devices using Cloud Firestore and Google Sign-In."
3. Review the architecture card the agent shows. Click Enable Firebase if it appears.
4. Wait for the agent to scaffold the Kotlin and Jetpack Compose project and provision the backend.
5. Preview the running app in the browser emulator. Toggle HD for 1200p streaming and test audio output if your app uses voice features.
6. Use the one-click screenshot button to send a live frame to the agent and request visual tweaks such as tighter padding or better contrast.

The agent uses the official Android CLI under the hood for scaffolding and Gradle builds. You can also request custom fonts; the agent downloads and applies them to your Compose theme.

## Publish to Your Personal Google Play Library

Testing in the emulator is fast, but real-device checks matter. From the publish panel:

1. Set up a Play account in a few clicks if needed.
2. Let AI Studio build and sign the Android App Bundle (.aab).
3. Publish to your personal Google Play library.
4. Install the app on your phone directly from Play.

This works with a standard Google account and requires no USB debugging or local keystore management. Personal library publishing is available in select markets.

## Secure Gemini Calls and Data Rules

Firebase AI Logic keeps credentials server-side. App Check uses Google Fraud Defense (formerly reCAPTCHA Enterprise) to confirm requests come from your genuine app, both in the emulator and after Play distribution.

Firestore Security Rules generated by the agent restrict access so users read and write only their own documents. Offline changes sync when the device reconnects.

If you later add more complex agent flows, review the Firebase AI Logic docs for model selection (Gemini 4 Hydrogen or Carbon) and spend controls.

## Tips for Better Prompts and Iteration

- Mention specific features (audio TTS, photo input for Gemini, multi-screen navigation) so the agent provisions the right services.
- Ask for custom typography early; the agent handles font setup.
- Capture emulator screenshots when UI feedback is hard to describe in text.
- Start with a simple prompt, then refine with follow-up requests rather than one giant specification.
- Test Google Sign-In and Firestore writes on a real device after publishing.

The HD emulator now boots with lower latency and supports real-time audio, so voice-driven features can be validated in the browser.

## Common Next Steps After the First Build

Once the app runs, open the generated Kotlin files to inspect the repository class that calls `Firebase.ai` and writes to Firestore. You can export the project or continue iterating inside AI Studio.

For production hardening, review the generated Security Rules, enable any additional App Check providers if needed, and monitor usage through the Firebase console. The agent already adds the Firebase BoM, so dependency versions stay consistent.

If your app needs on-device models later, combine this cloud setup with Gemini Nano via ML Kit as covered in related Android intelligence guides.
